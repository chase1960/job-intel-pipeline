# 03 · 同类岗位泛化：能力簇、关键词库、简历处方

这一段回答用户最实际的问题：**「这一堆同类岗位，到底要什么能力？我简历该怎么改？往里面塞哪些词？」**

## 一、岗位族归并与聚类

### 1.1 同族判定
三条同时满足才算同族：
- 职责重叠度 ≥60%（职责条目语义覆盖率）
- 能力簇交集 ≥2 个
- 职级相近（相差 ≤1 级）

反例：「AI 产品经理」与「AI 解决方案工程师」职责都提 AI，但一个是产品定义、一个是客户交付，不同族。

### 1.2 族内再分层
同族内部按**业务场景**分亚型，比按公司大小分更有用：
- 平台型（做通用能力/中台）
- 应用型（做具体场景产品）
- 商业化型（背收入/增长）
- 交付型（做项目落地）

同一份简历在这四类里的叙事重点完全不同，这是后续「简历处方」的前提。

## 二、能力点抽取

对每个 Q2 以上 JD，分别处理 `requirements` 与 `responsibilities`：

| 来源 | 抽什么 | 示例 |
|---|---|---|
| requirements（显性） | 明确要求的能力/经验/资质 | 「3 年以上 B 端产品经验」→ B端产品经验 |
| responsibilities（隐性） | 从职责反推需要的能力 | 「负责 ROI 建模与投放复盘」→ 归因建模 / 投放效果评估 |

规则：
- 能力点写成**动宾短语或名词短语**，不抄整句
- 保留原文片段作为证据，落 `evidence[]`
- 一条 JD 抽 8–15 个能力点即可，不要变成抄 JD

## 三、信号四分类（沿用 job-competency-analyzer 的阈值，保持体系一致）

| 类型 | 判定 | 处理 |
|---|---|---|
| 必备 | requirements 中 ≥40% 岗位提及，或 responsibilities 中 ≥60% 隐含需要 | 进能力簇主表 |
| 优先 | 带「优先/加分/更佳」修饰，或少数岗位明确要求 | 进加分项 |
| 套话 | 几乎人人写、职责中无对应体现、无区分度 | 合并为「基础职业素养」，降权 |
| 差异化 | 只在特定亚型/公司出现，代表该方向特征 | 按亚型分组单列 |

套话识别举例：「沟通能力强」「有责任心」「抗压能力好」「热爱互联网」——这些不进简历关键词，也不计入差距。

## 四、能力簇

- 数量 3–6 个，簇名 4–8 字动宾结构（如「用户增长操盘」「商业化建模」「复杂项目推进」「技术方案理解」）
- 每簇含：簇名、定义、能力项列表（带出现率 X/N）、2–3 条 JD 原文证据
- 样本量自适应：N<10 只做定性归纳，写「多数/部分/个别」，不做百分比推断

## 五、关键词三级库

这是给用户「直接抄」的产物，必须分层，否则会变成无脑堆词。

### L1 必命中（简历必须有）
来源优先级：岗位标题词 > 前 3 条要求 > 全文出现 ≥3 次的词 > 职责动词名词化。
每个 L1 词必须能对应用户**真实做过**的一件事；对不上的，转 L2 或不放。

### L2 加分（有则更好）
优先项、工具栈、方法论名（`SQL` `Figma` `dbt` `A/B 测试` `OKR` `敏捷` `PMP`）。

### L3 语境词（决定「像不像内部人」）
业务指标（`GMV` `留存` `ARR` `CAC` `LTV` `人效`）、场景词（`冷启动` `出海` `私有化` `信创` `降本增效`）、组织词（`跨部门` `虚线汇报` `双线汇报`）。

### 禁用词
- 自己没做过的技能（面试一问就穿）
- 空泛形容词（`优秀的` `极强的` `丰富的`）
- JD 里没有的自造概念（显得不懂行）
- 与岗位族无关的旧技能堆砌（占版面、稀释重点）

### 词频与位置
- 每个 L1 词在简历中出现 2–3 次为宜（摘要 1 次 + 经历 1–2 次），超过 5 次像堆砌
- L1 集中在「摘要 + 技能区 + 最近一段经历的前两条 bullet」
- 缩写在首次出现时写全（`大语言模型（LLM）`），兼顾 ATS 与人类阅读

## 六、简历处方（每条必备能力一条处方）

模板见 `assets/resume-prescription.template.md`，核心是五段式：

1. **岗位要什么**：能力簇 + JD 原话
2. **我有什么**：最贴近的真实经历（项目/职责）
3. **差在哪**：直接匹配 / 可迁移 / 缺失
4. **怎么改**：bullet 改写公式 `动作 + 对象 + 机制/方法 + 量化结果 + 与岗位的连接`
5. **放哪里**：摘要 / 技能区 / 经历首条 / 新增项目段

改写示例（真实经历，不编造）：

```
原：负责公司会员体系的日常运营和活动策划。
改：主导会员成长体系从 0 到 1 搭建（等级/权益/任务三模块），上线 3 个月付费会员转化率 +18%，
    月留存提升 6pt，直接支撑年度续费 GMV 增长 2300 万。
```

处方纪律：**只重排、重写、补量化，不新增没做过的职责**。缺的能力老实写进「差距」，给补法（一个小项目、一个可验证产出），不要塞进简历。

## 七、还要给「市场分布」一页

用户需要知道自己在跟谁竞争：
- 岗位数量按城市/公司类型/级别的分布
- 薪资带宽的 P25/P50/P75（样本 ≥10 才给分位，否则给区间）
- 必备能力的出现率排序
- 哪些能力是「人人都有」（不具备竞争力）vs「稀缺」（可作为差异化）

## 八、输出结构

```
岗位族：AI 应用产品经理（N=23，Q2+ 19 条）
├── 族内亚型分布：应用型 11 / 商业化型 6 / 平台型 4 / 交付型 2
├── 能力簇（4）
│   ├── 场景产品定义（17/19）
│   ├── 数据与效果验证（14/19）
│   ├── 跨团队推进（12/19）
│   └── 商业化理解（7/19，差异化）
├── 关键词三级库（L1 12 个 / L2 15 个 / L3 9 个）
├── 简历处方（按能力簇给 4–6 条）
├── 市场分布（城市/薪资/公司类型）
└── 数据局限（样本量、来源偏差、时间窗口）
```
