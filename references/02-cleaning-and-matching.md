# 02 · 清洗与匹配

两件事必须分开做：**先判断这条岗位数据是否可信可用（清洗），再判断它和你是否合适（匹配）**。混在一起做，会出现「因为不匹配所以判定数据有问题」的自我欺骗。

## 一、五关清洗

### 关 1 完整性
必需：公司、标题、城市、职责 ≥2 条、要求 ≥2 条、来源链接。
缺职责或要求 → 只能做市场统计，不能进能力分析。

### 关 2 时效性
按 01 的规则换算日期，落 `freshness`：`fresh` / `normal` / `stale` / `aged` / `unknown`。
`aged`（>90 天）不删，但排序时降权并显式标注「可能已关闭」。

### 关 3 真实性
判 `authenticity`：`verified`（官方源）/ `likely`（大平台且信息完整）/ `suspect`（中介、信息矛盾、疑似人才池）/ `fake`（收费、培训贷、虚假薪资）。
`suspect` 保留但标黄；`fake` 剔除并给用户一句风险提示。

### 关 4 一致性
交叉检查四处矛盾：
- 标题说「经理」但职责全是执行 → 实际是专员岗
- 要求写「3 年」但职责出现「主导战略」→ 实际要更高级别
- 薪资带宽跨度 >3 倍（如 15–50K）→ 定级未统一，谈判空间大但预期混乱
- 「不限经验/不限学历」+ 高薪 → 高概率销售或培训贷

### 关 5 归一化
- **标题归一**：映射到岗位族 + 职级（`P1–P3` 初级 / `P4–P5` 中级 / `P6+` 高级 / `M` 管理），保留原始标题
- **技能归一**：同义合并（`LLM`=`大模型`=`大语言模型`；`AIGC`⊂`生成式AI`）
- **地点归一**：`北京·朝阳`→`北京`；`远程` 单列
- **薪资归一**：统一为月薪 K 或年薪万，标注 `13薪/14薪`、是否含奖金

## 二、质量分 Q0–Q3

| 等级 | 判定 | 用途 |
|---|---|---|
| Q0 | 无职责无要求 / 链接失效 / `fake` | 丢弃，不进表 |
| Q1 | JD 模板化、要求与标题错位、信息缺一半、`suspect` | 只进市场统计，不做能力与单岗深解 |
| Q2 | 信息完整、时效 `fresh/normal`、来源可核 | 可做匹配与聚类 |
| Q3 | Q2 基础上含业务背景、团队信息、指标或技术栈线索 | 可做单岗深解与隐性需求推测 |

Q3 通常只占 20–30%，这是正常的；不要为了凑 Q3 而把 Q1 硬升。

## 三、匹配模型

### 3.1 先过 Gate（红线）

红线来自 Stage 0 画像卡的「硬条件 + 红线」。命中任一 → `gate=blocked`：
- 学历/证书/语言等**法定或硬性门槛**
- 年限差 >3 年（要求 8 年，你 3 年）
- 城市不在可接受范围且不支持远程
- 薪资上限低于你的下限 20% 以上
- 用户红线（外包驻场、单休、长期出差等）

Gate 结果三种：`pass` / `warn`（可谈，如年限差 1–2 年）/ `blocked`。
`blocked` 不进入评分，直接进「放弃档」并写原因码。

### 3.2 再算分

```
M = 100 × (0.7 × 必备覆盖率 + 0.3 × 加分覆盖率) × 门槛系数 × 时效系数
```

**必备覆盖率**：岗位必备能力簇（Stage 3 产出，单岗时现场抽取）中，用户覆盖的比例。
- 直接匹配 = 1.0
- 可迁移 = 置信度折算（高 1.0 / 中 0.7 / 低 0.4）
- 无 = 0

**加分覆盖率**：优先/差异化能力簇的覆盖比例，同上折算。

**门槛系数**：`pass=1.0`，`warn=0.75`。
**时效系数**：`fresh=1.0`、`normal=0.95`、`stale=0.85`、`aged=0.6`、`unknown=0.9`。

### 3.3 结果分档

| 档位 | 分数 | 建议动作 |
|---|---|---|
| 主攻 | M ≥ 75 且 gate=pass | 优先定制简历，7 天内投 |
| 可试 | 55 ≤ M < 75 | 有内推或叙事强可投，否则先补差距 |
| 放弃 | M < 55 或 gate=blocked | 记录原因，不投入时间 |

**原因码**：`EXP_OVER`（经验超限）/ `DOMAIN_MISS`（领域不匹配）/ `GATE_FAIL`（硬门槛）/ `STALE`（时效过期）/ `SUSPECT`（真实性存疑）/ `LEVEL_MISMATCH`（级别错位）。

### 3.4 理由必须可追溯

每个分数附三行：

```
匹配理由：3 年 C 端产品经验 + 做过激励体系，命中「用户增长」「留存提升」两个必备簇
支撑证据：简历「XX项目：DAU 从 8 万到 21 万，留存 7 日 +12pt」
主要缺口：无 B 端商业化经验（必备簇 3），可迁移度低
```

没有证据出处的分数一律不许输出。

## 四、反向清洗需求本身

用户的诉求经常是矛盾的：「想转 AI 但不想写代码」「要稳定又要高成长」「只看大厂但要 3 个月内转岗」。清洗需求的做法：

1. 把诉求拆成 **硬条件 / 软偏好 / 红线** 三类，写进画像卡
2. 找出互斥项，直接指出来（「A 与 B 在当前市场同时满足的比例很低」）
3. 给出可执行的替代方案（「先投 AI 应用侧产品岗，比纯算法岗门槛低且用得上你的 C 端经验」）

这步做不好，后面采得越多越乱。

## 五、排序与展示

默认排序：`档位 → M → 时效 → 公司优先级`。不要按发布时间排——最新不等于最合适。

表格必含列：`匹配分`、`档位`、`岗位`、`公司`、`城市`、`薪资`、`级别`、`发布时间`、`时效`、`质量分`、`核心要求（3条）`、`主要缺口`、`匹配理由`、`来源`。

> 给用户看的时候，「主要缺口」比「匹配理由」更有用——它决定要不要花时间。
