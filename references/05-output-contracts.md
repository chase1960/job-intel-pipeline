# 05 · 交付契约

同一批数据，用户在不同阶段要的东西不一样。选错粒度，等于没交付。

## 一、三种交付粒度

### A. 岗位速览表（采集完、要筛）
用途：一眼看出投哪些、跳过哪些。
形态：飞书电子表格 / Excel（`sheet` skill），字段固定，可筛选排序。

| 列 | 说明 |
|---|---|
| 匹配分 | 0–100，≥75 绿、55–74 黄、<55 灰 |
| 档位 | 主攻 / 可试 / 放弃 |
| 岗位 / 公司 / 城市 | 原始标题 + 归一后的岗位族 |
| 级别 | P1–P3 / P4–P5 / P6+ / M |
| 薪资 | 归一为月薪 K 或年薪万，标注几薪 |
| 发布时间 / 时效 | YYYY-MM-DD + fresh/normal/stale/aged |
| 质量分 | Q1–Q3 |
| 核心要求 | 3 条，逗号分隔 |
| 主要缺口 | 1 条，最有杀伤力的那个 |
| 匹配理由 | 一句话，含证据 |
| 原因码 | 放弃档必填 |
| 来源 | 平台名 + 链接（可点击） |

排序：档位 → 匹配分 → 时效。**不要按发布时间排。**

### B. 岗位族报告（决定主攻方向）
用途：看清「这个方向到底要什么能力、市场长什么样、我该怎么改简历」。
形态：飞书文档 / Markdown → 可再导 Word。

结构：
1. 结论先行（3 条：主攻方向、最大优势、最大短板）
2. 样本与局限（N、来源分布、时间窗口、偏差说明）
3. 能力簇表（簇名 / 出现率 / 证据 / 是必备还是差异化）
4. 关键词三级库（L1/L2/L3/禁用词）
5. 简历处方（4–6 条，按能力簇）
6. 市场分布（城市、公司类型、级别、薪资区间）
7. 竞争位置（我的能力覆盖 vs 市场要求的缺口图）
8. 下一步（投哪类岗、补哪个能力、怎么补）

### C. 单岗作战卡（决定投某家）
用途：投递前一页看完，面试前再复习。
形态：Markdown 卡片或一页 PDF，模板见 `assets/jd-decode-card.template.md`。
要求：**一页装得下**。超过一页说明没做减法。

### D. 求职看板（可选，持续跟踪）
形态：单文件 HTML 或飞书多维表格。
要素：漏斗（采集→主攻→已投→面试→Offer）、状态流转、跟进提醒（7/14/21 天）、匹配分分布。
看板是「跟踪工具」，不是「分析工具」，不要把它做成第二份报告。

## 二、字段与命名规范

- 日期一律 `YYYY-MM-DD`，相对时间保留原文在备注列
- 薪资统一口径：月薪 `K` 或年薪 `万`，注明 `×13/×14`、是否含绩效
- 公司名用工商全称或市场通用名，**同一批内保持一致**
- 文件/表命名：`岗位族_城市_YYYYMMDD`、`公司_岗位_YYYYMMDD`
- 不出现会话 ID、agent ID、临时哈希作为文件名

## 三、落库建议

| 场景 | 落地方式 |
|---|---|
| 一次性筛选 | 飞书表格，冻结首行 + 条件格式标色 |
| 多轮迭代（追加城市/调条件） | 飞书多维表格，字段化，保留历史不改结构 |
| 需要给非技术同事看 | 飞书文档，带结论与图表 |
| 个人本地管理 | Excel + `sheet` skill，公式算匹配分可复核 |

多轮迭代的纪律：**在原表上加字段、加行，不重建表**。重建会让用户之前的批注和筛选全部失效。

## 四、图表建议（少而准）

- 匹配分分布直方图（看池子质量，而不是看单个岗位）
- 能力簇覆盖雷达（我 vs 市场必备簇）
- 时效漏斗（采集→去重→时效→Q2→主攻）
- 薪资带宽箱线或区间条（样本 ≥10 才画）

不要画「岗位数量趋势折线」——除非有 ≥3 个时间点的同源数据，否则是伪趋势。

## 五、交付前自检

- [ ] 结论在第一屏，不在文末
- [ ] 每个数字有来源或标注「未披露」
- [ ] 放弃档给了原因码，不是默默消失
- [ ] 简历建议全部可追溯到真实经历
- [ ] 假设与事实视觉上能区分（标签或颜色）
- [ ] 文件名是人能看懂的名字
