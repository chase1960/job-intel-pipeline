# 04 · 单岗深解与公司业务推测

## 核心命题

**招聘启事不是需求清单，是一次预算承诺。** 公司先决定解决问题，再批编制，再发 JD。所以 JD 的真实含义不是「我们要什么人」，而是「我们要解决什么问题、我们缺哪块能力」。

从这个命题出发，单岗深解要回答四个问题：
1. 这个岗位在组织里是干什么的（不是title，是产出）
2. 公司为什么现在招（业务触发点）
3. 他们真正怕招错什么人（隐性门槛）
4. 我拿什么证据能降低他们的不确定性

## 一、5 层解码

### 第 1 层：标题——它是什么，更要知道它不是什么
- 看职责产出，不看名词。「AI 产品经理」可能实际是「数据标注与评测运营」。
- 判断方法：把前 3 条职责翻译成「交付物」，若交付物是文档/原型/指标 → 产品；是数据/看板 → 分析；是客户方案 → 解决方案；是排期/验收 → 项目。

### 第 2 层：必备 vs 加分
- 必备：前 3–5 条要求、标题里出现且正文强化的词、跨段重复 ≥3 次的词、「必须/要求/硬性」措辞
- 加分：「优先/加分/更佳/熟悉者优先」、出现在福利段或公司介绍里的技能
- 经验法则：**JD 列 15 条要求时，真正不可谈的通常只有 3–5 条**。判断标准——「如果候选人极强但缺这一条，会不会被拒？」

### 第 3 层：职级看动词，不看年限
| 动词族 | 级别 |
|---|---|
| 协助 / 支持 / 在指导下 / 参与 | 初级 |
| 负责 / 执行 / 独立完成 / 跟进 | 中级 |
| 主导 / 设计 / 搭建 / 推动 / 复盘 | 高级 |
| 规划 / 定策略 / 建体系 / 带团队 / 对结果负责 | 专家或管理 |

矛盾信号：写「5 年经验」但职责全是「协助/支持」→ 实际是中初级岗；写「3 年」但要求「主导/定策略」→ 实际要高级。**动词比年限诚实**。

### 第 4 层：公司语境
同一份技能清单，在不同公司含义不同：
| 公司类型 | 他们要的人 |
|---|---|
| 产品型大厂 | 体系化、能对齐多方、在大规模约束下做取舍 |
| 创业公司（A–C 轮） | 一人多岗、能容忍模糊、自己定义流程 |
| 外包/交付型 | 客户导向、流程服从、抗变更 |
| 国企/央企/金融 IT | 合规意识、稳定性、材料与汇报能力 |
| 外企中国区 | 跨时区沟通、矩阵汇报、英文书面 |

这一步决定「你像不像他们的人」，比技能匹配更影响面试通过率。

### 第 5 层：真实需求
把 JD 反译成一句话：「他们正在 ___，所以需要一个能 ___ 的人，在 ___ 时间内做出 ___」。
写不出这句话，说明还没读懂。写出来后，它就是整份作战卡的主线。

## 二、暗语词典（含置信度与反例提醒）

| 表述 | 大概率含义 | 置信度 | 反例提醒 |
|---|---|---|---|
| 快节奏、能抗压 | 人手紧、需求变更频繁、可能有历史技术债 | 中 | 也可能是正常业务旺季 |
| 一人多岗、多面手 | 编制少、职责边界模糊 | 中高 | 初创正常，大厂则异常 |
| 自驱、不需要人带 | mentor 弱、上手期短 | 中 | 也可能是团队成熟、默认你会 |
| 从 0 到 1 | 没有现成流程，要自己定义 | 高 | 需确认「0」是业务还是团队 |
| 舒适区、结果导向 | 只看产出，过程支持少 | 中 | — |
| 有竞争力的薪资 | 通常低于市场或不透明 | 中 | 少数公司确实守规矩不写数 |
| 弹性工作 | 可能意味着加班无边界 | 低 | 也可能真弹性 |
| 大牛团队、扇平化 | 决策集中或个人英雄主义 | 低 | 慎用，易过度解读 |
| 优先/加分 | 真实门槛可能低于描述 | 高 | 但强竞争岗会真按此筛 |
| 长期有效、人才池 | 非紧急招聘或幽灵岗 | 高 | — |
| 储备干部、管培 | 轮岗、定岗不确定 | 中 | 好公司是真培养 |
| 急聘/ASAP | 替补需求或项目告急 | 高 | 也可能是常规话术 |

用法纪律：暗语只是**先验**，必须用公司信息、JD 细节、面试回答去验证。把暗语当结论写，是最常见的翻车方式。

## 三、岗位生命周期与紧迫度

### 3.1 生命周期四型
| 类型 | 识别信号 | 对求职者的含义 |
|---|---|---|
| 新设（0→1） | 职责宽、无前任痕迹、「搭建/建立」、汇报关系模糊 | 高风险高回报，需要自带方法论，前 6 个月定生死 |
| 替补 | 职责具体、有清晰流程与文档要求、可能有交接描述 | 有前任预期在，容易被比较；问清前任为何离开 |
| 扩张 | 同团队同期多个同类岗、有成熟 SOP | 资源相对充足，但晋升竞争激烈 |
| 重组 | 职责跨两个职能、汇报线奇怪、岗位名新造 | 边界不清、政治风险高，先问清汇报线与决策权 |

### 3.2 紧迫度信号
- 时间词（ASAP/急聘/本月到岗）→ 高
- 薪资带宽极宽 → 定级未统一，谈判空间大
- 同时多地同岗 → 规模化扩张
- 挂网 >90 天仍在 → 要么要求过高，要么岗位本身有问题
- 要求清单又长又杂 → 用人方没想清楚，或 HR 拼凑

## 四、SCALE：把单岗放回岗位族与公司

单个 JD 是噪音，成组的 JD 才是信号。判断任何一条招聘信息时跑五问：

- **S（Stack）** 技术栈/工具：JD 里最诚实的部分。新出现的工具（近半年才有）→ 新能力建设
- **C（Cluster）** 集群：同职能同季度 ≥3 条 → 战略投入；1 条 → 噪音
- **A（Altitude）** 高度：大量招资深/总监 → 重建团队或新设部门；大量招初级 → 执行为主
- **L（Location）** 地点：新城市首现 + 合规/销售岗 → 市场进入
- **E（Evidence）** 反证：JD 提到的业务/产品，公司官网/财报是否已公开？**与公开叙事矛盾的那条，价值最高**

> 用于求职者的直接价值：判断这个岗位是「真扩编」还是「填坑」，以及半年后这个团队会不会被裁。

## 五、公司三段研究

### 5.1 业务（他们怎么赚钱）
- 收入结构：卖产品/卖服务/卖流量/卖订阅？一次性还是经常性？
- 客户：To B 还是 To C；大客户集中度；客单价与决策链
- 产品线：主力产品是什么，这个岗位服务于哪条线
- 单位经济：毛利率大致水平、获客方式（这决定岗位的 KPI 压力）

来源优先级：官网产品页与定价页 → 招股书/年报/财报电话会 → 融资公告 → 行业媒体深度稿 → 招聘 JD 自身（业务描述段）。

### 5.2 阶段（他们现在在哪）
- 生命周期：验证期 / 增长期 / 规模化 / 成熟守成 / 转型或收缩
- 组织信号：招聘结构（研发多还是销售多）、是否新设部门、是否大量招总监
- 资金信号：最近一轮融资时间与金额、是否盈利、是否在降本（招聘量骤降、岗位合并）
- 人力信号：岗位挂网时长、同岗反复重发、前任任职时长（可查公开履历）

阶段判定直接影响「这个岗位的 KPI 是什么」：增长期看增速，成熟期看利润率与人效，转型期看新业务验证。

### 5.3 市场（外部环境）
- 赛道位置：头部/腰部/挑战者；直接竞品 2–3 家
- 竞争强度：是否在打价格战、是否在抢同一批人才（同岗薪资水位）
- 政策与合规：资质、数据合规、行业监管（决定岗位是否需要证书/合规经验）
- 人才供需：同岗在招数量、薪资带宽变化（供不应求 → 门槛可谈）

写这段时要标来源与时间，市场结论最容易过期。

## 六、要求 ↔ 业务指标矩阵

把每条核心要求翻译成「公司哪个指标会因此变化」。这张表是面试准备的弹药库。

| JD 要求原文 | 解码后的实际需求 | 对应的业务目标 | 可能关联的 KPI | 面试大概率考 |
|---|---|---|---|---|
| 负责用户增长策略 | 增长停止，需要新抓手 | 规模扩张 | DAU/新增/ROI | 「你做过最成功的一次拉新，成本多少」 |
| 搭建数据看板与归因 | 决策靠拍脑袋，缺可信数据 | 精细化运营 | 数据覆盖率/决策时效 | 「口径不一致怎么处理」 |
| 推动跨部门协作 | 部门墙严重，项目推不动 | 组织效率 | 项目交付周期 | 「推不动的时候你怎么办」 |
| 控制成本/提升人效 | 利润率承压 | 降本增效 | 毛利率/人均产出 | 「你如何衡量投入产出」 |
| 从 0 到 1 搭建体系 | 新业务试水，无成熟路径 | 新赛道验证 | 首年目标达成率 | 「没有资源时你怎么起步」 |

规则：
- 与公司主战略高度一致的要求 → **面试必考**，简历必须放最显眼位置
- 与主战略关系弱的要求 → 大概率是 HR 堆砌，不必为它改简历
- 一项要求对应多个指标时，取最下游那个（更接近这个岗位的实际考核）

## 七、隐性需求假设（H1–H3）

JD 写不出的东西，用假设的方式补，但必须可验证。每条假设五个字段：

```
H1：他们真正缺的是「能把 AI 能力落成可售卖产品的人」，而不是算法专家
支撑证据：[事实] JD 要求「商业化落地」「跨团队推动」，但未要求算法/论文
         [公开推断] 公司近半年 AI 岗位集中在应用侧，无算法岗新增
反证条件：若面试中反复追问模型训练细节，则此假设不成立
验证动作：面试问「这个岗位前 6 个月最重要的交付物是什么，由谁验收」
置信度：中高
```

三条假设的推荐分工：
- **H1 业务假设**：这个 hire 要解决什么业务问题（增长/降本/合规/新产品）
- **H2 能力假设**：他们最怕招错的是哪种能力（落地能力/客户沟通/从 0 到 1）
- **H3 组织假设**：这个岗位在组织里的真实位置（新设/替补/临时项目/双线汇报）

### 验证动作清单（求职者可直接执行）
| 想验证 | 动作 |
|---|---|
| 岗位是否真新设 | 查该团队公开履历，是否有前任；JD 是否含交接/流程描述 |
| 业务是否真投入 | 查公司官网/公众号/财报近 6 个月是否提该业务；是否有配套岗位 |
| 汇报线与决策权 | 面试问「这个岗位向谁汇报、预算与排期谁定」 |
| 团队真实规模 | 面试问「团队现在几个人、分工怎么切」；查公开员工数变化 |
| KPI 压力 | 面试问「这个岗位第一年怎么算做得好」 |
| 岗位是否填坑 | 问「这个位置上一任做了多久、为什么离开」 |

## 八、推断纪律

1. **三证据原则**：一个结论至少 3 条独立证据（不同来源/不同类型），否则降级为假设。
2. **单一信号不下结论**：一条岗位、一条新闻、一句暗语都不构成判断依据。
3. **标注反证条件**：每个假设写清「什么情况下我是错的」，防止自我确认偏误。
4. **区分事实与叙事**：公司官网说的是「想让你相信的」，财报与招聘结构是「实际在做的」，两者矛盾时以后者为准。
5. **不做人格与道德判断**：可以判断业务风险与组织风险，不评价公司的人「好/坏」。

## 九、单岗作战卡输出结构

```
1. 一句话结论：值不值得投（M 分 + 档位 + 核心理由）
2. 岗位到底是什么：5 层解码摘要 + 生命周期判定
3. 真实需求假设：H1/H2/H3（含证据、反证、验证动作、置信度）
4. 硬门槛与隐性门槛：必须满足 / 可谈 / 需要解释的
5. 我的匹配：命中能力（带证据）/ 缺口（带补法）
6. 简历改 3 处：改哪条 bullet、怎么改、为什么
7. 关键词：L1 必放 8–12 个
8. 面试预判 5 题 + 每题答题主线（STAR 骨架）
9. 我要问对方 3 个问题（用于验证假设与避坑）
10. 风险与未知：未披露信息、需要警惕的信号
```
