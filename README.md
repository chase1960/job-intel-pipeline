# job-intel-pipeline · 求职岗位情报流水线

把「帮我找工作」拆成一条带闸门的流水线：**全网采集 → 清洗与匹配 → 同类岗位泛化 → 单岗深解与公司业务推测 → 结构化交付**。

不是第 21 个「改简历工具」。市面上 90% 的求职 skill 都在解决「已有 JD 之后怎么改简历」，本项目补的是它们集体缺失的两段：**岗位数据的清洗闸门**，和**把岗位当公司经营问题的解去反推**。

> Agent Skill 形态（`SKILL.md` + `references/` + `assets/`），适用于 Claude Code、豆包工作、Cursor、Codex 等支持 SKILL.md 的运行时。

## 为什么不一样

| 常见做法 | 本项目做法 |
|---|---|
| 关键词匹配打分 | 能力簇语义匹配，可迁移能力按置信度折算 |
| 采到就投 | Q0–Q3 质量分 + 时效 + 真伪 + 一致性四关清洗，废岗剔除并留原因码 |
| 关键词堆进简历 | L1/L2/L3 三级词库 + **禁用词**，每个 L1 必须对应真实经历 |
| 分析 JD 写了什么 | 5 层解码 + 岗位生命周期 + 要求↔业务指标矩阵，推断他们真正缺什么 |
| 猜公司想要什么 | 隐性需求写成 H1–H3 假设，每条带**反证条件**与**面试验证动作** |
| 一个巨型 prompt | 总控 + 5 个 reference，按需加载，跑到第 10 轮也不漂移 |

## 流水线

```
Stage 0 画像卡（硬条件 / 软偏好 / 红线）
   ↓
Stage 1 全网采集（S 级官网ATS → A 级校招/政府 → B 级平台 → C 级搜索）
   ↓  闸门：每条有来源链接 + 发布时间
Stage 2 清洗与匹配（五关清洗 · Q0–Q3 · Gate · 加权评分）
   ↓  闸门：每条有质量分、匹配分、理由、证据
Stage 3 同类泛化（岗位族 → 能力簇 → 关键词三级库 → 简历处方）
   ↓  闸门：每条能力 ≥2 条 JD 证据
Stage 4 单岗深解（5 层解码 · 生命周期 · 公司三段 · 假设 H1–H3）
   ↓  闸门：每个假设有验证动作
Stage 5 交付（速览表 / 岗位族报告 / 单岗作战卡 / 求职看板）
```

## 快速开始

装好后不用记命令，直接用自然语言说目标。**岗位族 + 你的画像**这两项给了，输出质量差一个量级。

```
用 job-intel-pipeline 帮我找工作：AI应用产品经理，上海优先，接受杭州，近一个月，15K以上
```

只采集，先看池子：

```
全网抓一批 {岗位族} 的岗位，{城市}，近30天，只用官网/ATS和校招聚合源，先给我速览表
```

采集完要决策：

```
按我的情况筛这批岗位：3年B端产品、想转AI应用、薪资不低于20K、不接受外包驻场。
给我主攻/可试/放弃三档，每档写清理由和主要缺口
```

要能力画像和简历改法：

```
把这批 {岗位族} 岗位归并成岗位族，提炼核心能力簇，给我关键词三级库，
再告诉我简历该改哪几条 bullet、怎么改
```

拆单个岗位（贴 JD 或链接）：

```
拆解这个岗位 [JD 或链接]：他们真实缺什么能力、结合这家公司的业务和发展阶段推测可能的业务重点，
告诉我值不值得投、简历改3处、面试可能问什么
```

持续盯盘（接定时任务）：

```
每周一早上9点，扫一遍这10家目标公司的新岗位，匹配度≥75 的发我
```

## 指令里最好带的 6 个要素

| 要素 | 作用 | 例子 |
|---|---|---|
| 岗位族 | 生成关键词矩阵 | AI应用产品经理 |
| 城市优先级 | 决定采集范围与打分 | 上海 > 杭州 > 远程 |
| 时间窗 | 时效过滤 | 近30天 |
| 硬条件 | Gate 门槛，避免白算 | 20K以上、不要外包 |
| 你的画像 | 匹配分与缺口 | 3年B端、做过会员体系 |
| 交付形态 | 输出粒度 | 速览表 / 岗位族报告 / 一页卡 |

缺的项会被追问，最多 3 个。

## 关键设计

**质量分 Q0–Q3**：Q0 丢弃（无职责/失效/培训贷），Q1 只做市场统计，Q2 可匹配，Q3 可深解。没有这一步，模板化 JD 会把能力画像污染成「人人都要沟通能力」。

**匹配公式**：`M = 100 × (0.7×必备覆盖率 + 0.3×加分覆盖率) × 门槛系数 × 时效系数`。过期的好岗不会排在前面；不可谈的硬门槛不会被当成「软差距」。

**关键词三级库**：L1 必命中（标题词/前3条要求/重复≥3次）、L2 加分（工具与方法论）、L3 语境词（业务指标与场景）、外加**禁用词**（自己没做过、空泛形容词、JD 没有的自造概念）。

**隐性需求假设**：H1 业务 / H2 能力 / H3 组织，每条五字段——假设、支撑证据、反证条件、验证动作、置信度。没有反证的推断只是自我安慰。

**证据分层**：`[事实]` 原文可查 / `[公开推断]` 基于公开信息 / `[假设]` 待验证。三者视觉上必须能区分。

## 与其它 skill 的关系

本项目负责编排，不重复造轮子，可与以下 skill 串联：

- `job-matcher-collector` —— 多策略搜索与多源采集（Stage 1 引擎）
- `job-competency-analyzer` —— 能力点抽取、信号四分类、能力簇（Stage 3 前半）
- `skill-gap-mapper` —— 可迁移能力与差距补法（Stage 4 缺口部分）

单独使用也完整：不装这三个，仍可跑通全流程。

## 边界

- **不代投递、不代填表、不批量群发**。采集可以自动，投递必须你点头。
- **不编造经历和数字**。只重排、重写、补量化；缺的能力进「差距」，不进简历。
- **不绕过反爬与登录**。需登录的平台由你自行登录，单站请求间隔 ≥2 秒。
- **不采集招聘者个人隐私**，只取公开岗位信息。
- **推断给反证条件**。你可以用一次面试就推翻它，这正是它有用的原因。

## 方法论来源

- 招聘 5 层解码（标题 / 必备-vs-加分 / 动词判级别 / 公司语境 / 真实需求）
- SCALE 信号法（Stack / Cluster / Altitude / Location / Evidence）
- 招聘即预算承诺：岗位启事是比新闻稿更早的战略信号
- 岗位生命周期四型（新设 / 替补 / 扩张 / 重组）
- 模糊匹配双阈值（强匹配 ≥75 / 部分匹配 45–75 交人工复核）
